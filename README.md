# Markdown-It — сайт приложения

Статический двуязычный сайт Chrome-расширения Markdown-It. Обычные HTML/CSS и небольшой JavaScript; сборка, npm-пакеты, CDN, внешние шрифты, аналитика и формы не используются. Для работы опубликованного сайта нужен только статический хостинг.

- Главная: `https://dmitry-osin.github.io/md-it/`
- Полная политика: `https://dmitry-osin.github.io/md-it/policy`
- Допустимый ответ на адрес политики: перенаправление на `/md-it/policy/`.
- Автор: [dmitry-osin на GitHub](https://github.com/dmitry-osin).
- Ошибки и предложения: [GitHub Issues](https://github.com/dmitry-osin/markdown-it-issues/issues).

## Локальный запуск

Из корня сайта, с установленным Python 3.10+:

```sh
python scripts/serve.py
```

Откройте `http://127.0.0.1:8000/md-it/`. Другой порт: `python scripts/serve.py --port 8080`. Остановка — Ctrl+C.

Сервер намеренно воспроизводит префикс GitHub Pages и обычное перенаправление каталога политики. Простое открытие `index.html` через `file://` не подходит для проверки абсолютных путей `/md-it/`.

Языковые ссылки для проверки:

```text
http://127.0.0.1:8000/md-it/?lang=ru
http://127.0.0.1:8000/md-it/?lang=en
http://127.0.0.1:8000/md-it/policy?lang=ru
http://127.0.0.1:8000/md-it/policy?lang=en
```

Переключатель RU/EN меняет `html.lang`, тексты, доступные подписи, метаданные и реальные скриншоты. Выбор сохраняется в `localStorage`; параметр `lang` в ссылке имеет приоритет, затем якорь языка политики, сохранённая настройка и язык браузера. При блокировке хранилища переключение продолжает работать. На сайте сохраняется только предпочтение языка.

Без JavaScript главная остаётся доступна на русском, галерея показывает все четыре изображения, а политика содержит оба полных текста с `lang` у каждой версии. Для ссылки на раздел политики можно использовать, например, `policy/#en-network` или `policy/#ru-storage`.

## Проверки

```sh
python scripts/check.py
python -m unittest discover -s scripts -p 'test_*.py'
node --check assets/site.js
```

Python использует только стандартную библиотеку. Node нужен только для необязательной локальной проверки синтаксиса JavaScript; работа сайта и запуск локального сервера от него не зависят. Workflow выполняет обе проверки перед подготовкой публикации.

Проверки сверяют локальные ссылки и якоря, переводимые элементы, метаданные, атрибуты изображений, размеры скриншотов, RGBA-канал иконки, отсутствие абсолютных локальных путей в HTML и наличие каждого абзаца обеих версий `PRIVACY.md` в политике.

Браузерная проверка: обе страницы RU/EN; широкий и мобильный экран; отсутствие горизонтального скролла; смена языка и его сохранение при переходах; все вкладки галереи; Tab, Enter, стрелки, Home/End; видимый фокус; раскрытие FAQ; загрузка изображений; отсутствие ошибок консоли; прямой переход и перезагрузка `/md-it/policy`. Результаты — в `VERIFICATION.md`.

## GitHub Pages: действия владельца

1. Создайте или выберите отдельный репозиторий `dmitry-osin/md-it`. Сайт подготовлен без коммитов; добавление файлов в Git, коммит и push выполняет владелец.
2. Разместите файлы этого проекта в ветке `main` выбранного репозитория. Если основная ветка называется иначе, измените `on.push.branches` в workflow.
3. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**. При необходимости разрешите Actions в настройках репозитория. Доступность Pages для приватного репозитория зависит от плана GitHub.
4. Выполните push в `main` или запустите **Actions → Deploy static site to GitHub Pages → Run workflow**. Это запускает реальную публикацию.
5. Дождитесь успешных заданий `prepare` и `deploy`; при настроенной защите окружения подтвердите deployment в `github-pages`.
6. Проверьте публично без авторизации оба HTTPS-адреса, обе локали, иконку, скриншоты и повторное открытие `/md-it/policy`. После этого URL политики можно использовать при отправке расширения в Chrome Web Store.

Workflow подготовлен по актуальной официальной документации GitHub, проверенной 15.10.2026:

- [Custom workflows with GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
- [Configuring a publishing source](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

Используются `actions/checkout@v6`, `actions/configure-pages@v5`, `actions/upload-pages-artifact@v4` и `actions/deploy-pages@v4`; deployment использует окружение `github-pages` и разрешения `pages: write`, `id-token: write`.

Публикуется только явно собранный каталог `_site`: `index.html`, `policy/index.html`, `assets/`, `.nojekyll`, `robots.txt`, `sitemap.xml`. README, скрипты, `PRIVACY.md`, отчёт проверки, `.qa/`, Git и конфигурация CI не входят в Pages-артефакт. Исходники и пакет расширения в этом проекте отсутствуют. Не выбирайте публикацию всего корня ветки, если хотите сохранить этот состав артефакта.

## Обновление контента

Описание функций сверено с README, CHROMEWEBSTORE, PRIVACY и package.json расширения. Автор предоставил адрес карточки: [Markdown-It в Chrome Web Store](https://chromewebstore.google.com/detail/pbajjhnmfaopgjblomoecaaokihjajli). На 15.10.2026 карточка ещё ожидает публикации — это подтверждено автором и ответом магазина. Запрос сборки и ручная установка удалены из UI.

Статус меняется автоматически; редактировать сайт после публикации расширения не нужно:

1. При push, ручном запуске и раз в час (на 17-й минуте) GitHub Actions проверяет публичную англоязычную карточку через `scripts/store_status.py`. Проверка не требует ключей или доступа к аккаунту магазина.
2. Обычный HTTP 200 не означает публикацию: магазин возвращает его и для недоступной карточки. Скрипт проверяет метаданные конкретного ID и кнопку Add to Chrome; ответ с `empty-title`, `/error`, Item not available или HTTP 404/410 означает ожидание. Тайм-аут, HTTP 403/429/5xx, consent и неизвестная разметка считаются неопределённым результатом и сохраняют последний подтверждённый статус.
3. Предыдущие статус и версия читаются с опубликованного сайта. Плановая проверка без изменения этих данных не загружает артефакт и не запускает деплой. Изменение статуса или версии автоматически обновляет Pages; код и коммиты при этом не меняются. Push и ручной запуск обновляют сайт обычным способом. Если в плановом запуске прежний статус недоступен, деплой пропускается до следующей проверки.
4. В Pages-артефакте формируется `assets/store-status.json`. Браузер читает этот небольшой файл с того же сайта при открытии страницы, возвращении к вкладке и каждые пять минут активной вкладки. При ожидании видна надпись «Ожидает публикации», при подтверждённой публикации появляются ссылки магазина. Ошибка загрузки JSON сохраняет текущее состояние; при первом открытии используется ожидание. Проверка не отправляет запросы в Google из браузера посетителя и не использует сторонний CORS-прокси.

Версия читается из поля **Details → Version** англоязычной карточки. Номера из описания, отзывов или скриптов не используются. Значение проверяется по формату версии Chrome-расширения и записывается в `version` внутри JSON. Бейдж на главной показывает `v` и полученное значение только для опубликованной карточки с корректной версией. Если версия отсутствует или формат разметки магазина изменился, бейдж скрывается; при сетевом сбое сохраняются последние подтверждённые данные. Хардкода текущей версии в UI нет.

Проверить парсер на любом опубликованном расширении можно без изменения ID Markdown-It, записи файлов и публикации:

```sh
python scripts/store_status.py --probe-extension aapbdbdomjkkjkaonfhkkikfgjllcleb
```

Команда печатает JSON со статусом и версией указанного расширения. Парсер проверен на опубликованных карточках Google Translate и Mate Translate.

Потребуется один первоначальный push этих изменений, после которого работает расписание. Проверяется публичная карточка из runner GitHub; персональные ограничения аккаунта и региона посетителя не определяются. GitHub может задерживать scheduled runs; это не мгновенный мониторинг. Расписание действует на default branch и может быть отключено GitHub в публичном репозитории после 60 дней без активности — при необходимости включите workflow в Actions. [Официальные условия schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

Для локального сценария публикации временно измените `status` в `assets/store-status.json` с `pending` на `published`, проверьте UI и верните `pending`. Этот файл — начальное состояние для локального запуска; Actions формирует актуальную копию только в публикуемом артефакте. Без JavaScript доступна надпись ожидания и общая подсказка браузера. При изменении ID обновите ссылки `data-store-link` на обеих страницах, URL в `assets/site.js`, `assets/store-status.json`, `scripts/store_status.py` и соответствующие проверки.

Подсказки учитывают браузер и тип устройства локально: Chrome, Firefox, другие Chromium-браузеры, мобильное устройство и неопределённый браузер. Firefox пока в разработке — статус предоставлен автором. Для телефона предлагается Chrome на компьютере, а для других Chromium-браузеров совместимость не обещается. Используются обычный user agent и доступные низкоэнтропийные `userAgentData.brands/mobile`, без сохранения или отправки этих данных. Определение приблизительное: user agent может быть сокращён или подменён. Когда карточка опубликована, ссылка доступна в любом браузере; предупреждение не блокирует её. Смена RU/EN переводит и подсказки.

Переводы главной лежат непосредственно в HTML: пары `data-ru` / `data-en`, а доступные подписи — `data-aria-*` и `data-alt-*`. Никакого сетевого запроса для выбора языка нет.

Политика не сокращалась. По указанию автора email заменён на профиль GitHub и репозиторий для обращений; остальные положения сохранены. Локальная копия `PRIVACY.md` и HTML содержат одинаковые тексты обеих языковых версий. Исходный проект расширения не изменялся. При согласованном обновлении сначала замените локальный `PRIVACY.md`, затем выполните:

```sh
python scripts/policy.py
python scripts/check.py
```

Генератор обновляет только участок между `policy:start` и `policy:end`; оформление и навигация сохраняются. `docs/policy/` расширения изучена и адаптирована к общему оформлению, её PNG-иконка используется в сайте. Основная иконка и все восемь скриншотов скопированы побайтово; кадрирование, перерисовка и изменение пропорций не применялись.

После замены ассетов обновляйте оба набора скриншотов и проверяйте сохранение прозрачности PNG. При изменении домена или имени репозитория обновите `/md-it/` в HTML/JS, канонические адреса, Open Graph, robots, sitemap и путь в локальном сервере.

Сайт подготовлен локально. Коммит, push, публикация Pages и отправка в магазин при разработке не выполнялись.
